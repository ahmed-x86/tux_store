# Logging

Files: `crates/tux-abi/src/logging.rs`, `crates/tux-store/src/hub.rs`

All modules use the standard `log` macros (`log::debug!`, `info!`, `warn!`, `error!`).

## One sink for the whole process

Every `.so` carries its own copy of the `log` crate's global state, so a logger installed in the host would never see the modules' records. Each module therefore calls `tux_abi::logging::install(api)` automatically (inside the code generated by `export_module!`), which routes every record through the host's C callback `HostApi.log`. The host prints:

```
[   1.234s] INFO  tux_search::catalog   catalog: 7 sections, 12 packages with add-ons
```

(seconds since start, level, module path, message) on stderr.

## Level

```bash
TUX_LOG=debug ./tux-store     # error | warn | info (default) | debug | trace | off
```

The level is read once by the host and handed to the modules, so the filter is the same everywhere.

## Conventions

- `error!` — something failed that the user will notice.
- `warn!` — recoverable but notable: unusable `categories.json`, cache write failure, `xdg-open` failure.
- `info!` — milestones: modules loaded, transaction started/finished (exit code), catalog size.
- `debug!` — detail: number of indexed icon theme directories, undecodable messages.
- Panics are caught at the ABI boundary; the default panic hook still prints the message to stderr.

Host lines are prefixed `[host]` (module loaded / skipped).
